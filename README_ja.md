# Bookmark Organization

ローカルAIモデル・OpenRouter・ChatGPT契約枠を使うCodexで、Chromeのブックマークを整理するローカルWebアプリです。エクスポートしたブックマークファイルを読み込み、処理するフォルダーを選び、名前付け・フォルダー分けの指示を指定し、整理案を確認してから、Chrome互換のHTMLをダウンロードできます。

インポートした元ファイルを保持し、同じURLのブックマークも別々に保ちます。ページ取得に失敗してもブックマークは削除されません。エクスポート前に、ブックマークの識別情報、件数、URLごとの重複数、選択範囲外の変更がないことを検証します。

## できること

- すべてのブックマーク、1つのフォルダー、または複数のフォルダーをまとめて整理できます。
- ページを個別に分析し、「何をするためのページか」で命名、「どんな作業で探すか」でフォルダー分類します。埋め込み表現はフォルダー内で関連項目をまとめた並び順に使います。
- 元の名前や保存先と提案内容を比較し、検索や絞り込みで結果を確認して編集できます。保存した編集は新しい提案バージョンになります。
- 処理を一時停止・再開・キャンセルし、失敗した項目を手動で再試行できます。サーバー再起動後も進捗は保存されます。
- LM Studio・Ollama・OpenRouterから、生成モデルと埋め込みモデルを個別に選べます。
- コンテンツ分析には、ChatGPT契約枠を使うCodexも選べます。
- 名前付けとフォルダー分けを個別の指示で変更するか、現在の用途別ルールのプリセットを選べます。
- 保存済み結果を引き継ぎ、別のフォルダーを異なる指示で続けて整理できます。
- インターフェースは英語と日本語を切り替えられます。プリセットは日本語で命名し、カスタム指示では別の言語も指定できます。

LM StudioとOllamaの推論はローカルで実行されます。OpenRouterを選択すると入力がOpenRouterとモデル提供元に送信され、利用料金が発生する場合があります。Codexを選択すると分析入力がOpenAIに送信され、ChatGPT／Codexの契約枠を消費します。ブックマークの内容を取得するときは、リンク先のWebサイトにアクセスします。このアプリはChromeプロフィールを直接編集せず、モデルを自動ダウンロードすることもありません。

## 必要なもの

- Python **3.13** と **uv**。
- フロントエンドアセットのビルドに使うNode.js **26.5以降**とnpm **12.0.1以降**。
- 選択したモデルをインストールしたローカルの**LM Studio**または**Ollama** APIサーバー、または**OpenRouter**のアカウントとAPIキー。生成と埋め込みに別々のプロバイダーを使えます。
- Codexで分析する場合は、サーバーのPATHで使える**Codex CLI**と**ChatGPTログイン**。CLI **0.160.1**で検証しています。埋め込みには上記の別プロバイダーが必要です。

このプロジェクトはApple silicon搭載Macで開発・検証されています。モデルの実行は推論ランタイムが担い、このアプリにCUDA依存関係はありません。通常の運用ではPythonサーバーを1つと、選択したローカル推論ランタイムを使用します。

## はじめに

リポジトリのディレクトリで、次を実行します。

```sh
uv sync --locked
npm ci
npm run build
uv run --locked bookmark-organization
```

[http://127.0.0.1:8765](http://127.0.0.1:8765)を開きます。サーバーを停止するには**Ctrl+C**を押します。サーバーはループバックでのみ待ち受け、バックグラウンドワーカーを1つ管理します。データディレクトリごとにサーバープロセスを1つだけ実行してください。

フロントエンドアセットはローカルから配信され、CDNは使いません。フロントエンドのソースを変更した後は、`npm run build`で再ビルドしてください。

### モデルの接続

アプリの**設定**を開きます。LM StudioまたはOllamaを使う場合はローカルAPIサーバーも起動します。

| プロバイダー | ベースURL |
| --- | --- |
| LM Studio | `http://localhost:1234/v1` |
| Ollama | `http://localhost:11434/v1` |
| OpenRouter | `https://openrouter.ai/api/v1`（固定） |
| Codex（分析のみ） | エンドポイント不要・CLIのChatGPTログインを使用 |

コンテンツ分析と埋め込みをそれぞれ設定します。プロバイダーとエンドポイントを選び、**モデル一覧を取得・接続確認**を押して、候補から選ぶか正確なモデルIDを直接入力し、**保存**します。入力すると候補を絞り込めます。一覧の再取得でも入力値は保持されます。ファイル名ではなく、モデル一覧の取得時に返されるモデルIDを使用してください。モデルのインストールと読み込みはランタイム側で行います。

**Codex**を使う場合は、アプリを動かすマシンで`codex login`を実行してChatGPTログインを選び、コンテンツ分析のプロバイダーを**Codex（ChatGPT契約枠）**にして保存します。モデルは`gpt-6-luna`、推論は`low`で固定です。APIキー認証は拒否し、APIキーの環境変数もCodexに渡しません。一覧取得はログインとモデルカタログを確認し、推論はしません。実際のモデル利用可否は分析成功時に確認できます。URL・元の名前とフォルダーパス・上限内の取得本文がOpenAIに送信され、契約枠を消費します。ページごとに独立した一時セッションと分析用指示を使い、ツールを無効化し、返されたJSONをアプリ側で検証します。埋め込みには別に選んだプロバイダーを使います。サンプリングとアプリの出力トークン上限はCodexには適用されません。モデル応答の待機上限は適用し、キャンセルや期限超過時はCLIプロセス群を終了します。利用枠の上限に達した場合は、回復後に手動で再試行してください。[認証の公式資料](https://learn.chatgpt.com/docs/auth)と[自動実行の公式資料](https://learn.chatgpt.com/docs/non-interactive-mode)を参照してください。

初期選択は次のとおりです。

| 役割 | デフォルトのAPIモデルID | LM Studioの検証記録で使用したGGUF |
| --- | --- | --- |
| コンテンツ分析 | `qwen3.5-9b-uncensored-hauhaucs-aggressive` | HauhauCSの`Qwen3.5-9B-Uncensored-HauhauCS-Aggressive-Q6_K.gguf` |
| 埋め込み | `text-embedding-embeddinggemma-2` | unslothの`embeddinggemma-2-Q8_0.gguf` |

必要な構造化分析または埋め込みの役割を担える別のモデルも選べます。Ollamaではデフォルトと異なるモデル名が使われることがあります。LM StudioとOllamaにはループバックのエンドポイントを指定し、クラウドを経由するモデルは対象外です。OpenRouterは明示的な選択でのみ公式HTTPSエンドポイントに接続します。ローカルモデルの失敗時にクラウドへ自動切り替えはしません。[LM Studio APIドキュメント](https://lmstudio.ai/docs/developer/openai-compat)と[Ollama互換性ドキュメント](https://docs.ollama.com/api/openai-compatibility)を参照してください。

OpenRouterでは、APIキーをパスワード欄に入力して**モデル一覧を取得・接続確認**を押し、候補を選ぶかモデルIDを直接入力して**保存**します。モデルIDが分かっている場合は一覧取得を省略できます。接続確認はキーを検証し、分析には構造化出力対応のテキストモデル、埋め込みにはテキスト埋め込みモデルを表示します。接続確認だけでは推論しません。生成をOpenRouter、埋め込みをローカルにする組み合わせも使えます。分析では選択したブックマークのURL・元の名前とフォルダーパス・ページのタイトル・説明・上限内の本文を送信し、クラウド埋め込みではタイトルと分析結果のテキストを送信します。料金やデータの取り扱いはOpenRouterのアカウントとモデル提供元によります。[OpenRouterの導入手順](https://openrouter.ai/docs/quickstart)と[埋め込みの公式仕様](https://openrouter.ai/docs/api_reference/embeddings)を参照してください。

入力したキーはデータディレクトリの`credentials.json`に所有者のみ読み書きできる権限（0600）で保存し、`settings.json`・ジョブ履歴・API応答・画面には含めません。空欄なら維持し、新しいキーを保存すると次の処理開始・再開時に使います。保存したキーがない場合はサーバーの環境変数`OPENROUTER_API_KEY`を使用します。認証情報をGitに含めないでください。既存ジョブのプロバイダー・モデル選択は変わりません。OpenRouterにはモデルが対応する推論設定だけを送信します。繰り返しペナルティは2以下で、一部のモデルは思考オフでも推論を必須とします。認証・残高・利用頻度制限のエラーは区別して表示し、再試行は手動です。

推論設定のデフォルトは**ウェブアプリの設定を使う**で、**思考**は**オフ**です。このモードでは思考、温度、サンプリングを制御できます。サンプリング項目のチェックを外すと、無効化を示す中立値が送られます。**ランタイムの設定を使う**を選ぶと、思考、温度、サンプリングの上書きはランタイムのAPIデフォルトに委ねられます。どちらのモードでも、保存済みのランタイム設定は変更されません。新しいジョブにはアプリ設定がスナップショットとして保存され、既存のジョブでは選択内容が保持されます。ランタイムが管理するデフォルトは別途変更できます。

**モデル応答待ち**のデフォルトは**0＝無制限**です。0より大きい秒数を設定すると待ち時間を制限できます。一時停止すると、実行中のリクエストが返るまで待機します。キャンセルは無制限の待機中でもアプリ側の通信待ちを中断し、ジョブを終了します。詳細設定では、取得の制限、入力・出力の上限、クラスタリングのしきい値も設定できます。

### アプリの使い方

1. ChromeのブックマークをUTF-8のHTMLとしてエクスポートし、ファイルを読み込みます。
2. すべてのブックマーク、1つのフォルダー、または複数のフォルダーを選択します。子孫フォルダーも含まれ、重複する選択はまとめられます。複数のフォルダーは1つの処理範囲になります。保存先には、選択中のフォルダーのうち、別の選択フォルダーの中に含まれていないものを選びます。すべてのブックマークを処理するモードでは、`整理済み`というルートフォルダーが作成されます。
3. **今回の整理ルール**で名前付けとフォルダー分けのそれぞれに**プリセット**か**カスタム指示**を選びます。選択した項目の指示欄だけが有効になり、プリセットに戻しても入力内容は残ります。無効な欄の指示は適用されず、空欄のカスタム指示にはプリセットを使います。分析を開始して進捗を確認します。ブラウザーのタブを閉じても処理は停止しません。**一時停止**を押すと次の段階への移行を防ぎ、**再開**すると保存済みの進捗から続行します。サーバー再起動後、中断されたジョブは再開するまで一時停止状態になります。
   **キャンセル**は処理中・一時停止中のジョブを終了し、同じプロジェクトで新しい分析を開始できるようにします。元のブックマーク、ジョブ設定、保存済みの結果は保持します。キャンセル済みのジョブは再開・再試行・整理案作成ができません。アプリ側の通信を切断しますが、外部のモデル提供者が受付済みの処理を続ける場合があります。
4. 取得失敗と分析失敗を確認します。原因を解消してから**失敗分を再試行**を使います。取得に失敗したブックマークは元の名前のまま、`404`や`アクセス制限`などのフォルダーに残ります。分析失敗を含めるには、`要確認`への配置を明示的に許可してください。
5. 整理案を作成し、名前と保存先を比較します。名前や許可された保存先フォルダーを編集して保存します。保存のたびに新しいバージョンが作られ、元のインポートは変更されません。
6. 続ける場合は**別のフォルダーを続けて整理**を押し、次のフォルダーと指示を選びます。整理案と各編集は自動保存され、開き直すと最新の保存結果が出発点になります。対象外の名前・配置は維持されます。整理案の保存後に同じ項目を再処理する場合は、新しい整理として開始します。
7. 整合性検証に合格したらエクスポートします。これまでの保存済み整理結果がすべて含まれます。インポートした元ファイルもダウンロードできます。エクスポート結果は別のChromeプロフィールで確認してください。Chromeにインポートすると既存のブックマークに追加されます。

まず小さなファイルで試し、結果をChromeにインポートする前に提案を確認してください。カテゴリの品質はページ内容と選択したモデルによって異なります。用途が明確な単独項目もその用途のフォルダーに残します。用途を判断できない項目は`あとで整理`、明示的に許可した分析失敗は`要確認`に配置します。クラスタリングの距離計算に使うメモリの推定予算128 MiBを超える選択は、フォルダーをさらに分けて処理する必要があります。

### 名前とフォルダーの整理ルール

**現在のルール**プリセットでは、名前を`具体的な用途｜サイト・ツール・資料名`に統一します。一般サービスは`文章を翻訳｜DeepL`、GitHubはアプリ・CLI・ライブラリ・サンプル・まとめを区別し、必要な種類や言語だけを補足して`動画をダウンロード｜yt-dlp［CLI］`などにします。個別のドキュメントや記事はサイト全体ではなく、そのページで調べられる内容を名前にします。例：`正規表現の書き方を確認｜Python re`。

フォルダーは「どんな作業で探すか」で分類し、同じ用途の公式サイト・GitHub・記事をまとめます。AI・機械学習、画像・動画、開発・プログラミング、ファイル・文書、調査・学習、macOS・システム、生活・買い物を構成例とし、当てはまらない具体的な用途も使えます。複数の用途があるときは元の名前とフォルダーパスから探し方を推定します。整理先（全件モードでは`整理済み`）の配下に新しく作るフォルダーは2階層まで。下位用途が3件以上あり、同じ上位用途にほかの項目もある場合だけ下位フォルダーを作り、少数や重複する分類は上位に統合します。空の分類を先に作りません。`あとで整理`は一時的な保存先として定期的に見直します。名前にフォルダー階層を詰め込みません。

画面にもプリセットの折りたたみ式案内があります。**カスタム指示**では、名前の形式や言語、フォルダー構成を変更できます。例：「JSライブラリ関係、Python、ユーティリティ系で分ける」。カスタム分類で明示した少数項目のサブフォルダーも保持し、保存先の下は最大2階層とします。各分析には指示と開始時のツリーが保存され、後から指示を変更しても既存の分析には影響しません。既存ジョブは再開・再試行時も保存済みの命名・分類ルールを保持するため、新ルールを使うには新しく分析してください。整理案の手動編集は引き続き利用できます。

### JavaScriptページの取得（任意）

JavaScriptで描画されるページを取得するには、Chromiumをインストールし、**設定**で描画を有効にします。

```sh
uv run --locked playwright install chromium
```

取得機能はプライベートおよび予約済みのネットワーク宛先をブロックし、リダイレクト先を検証します。ワーカー全体で、描画されたサブリソースや手動再試行も含め、リクエスト開始の間隔を少なくとも0.5秒空けます。取得失敗は自動で再試行されず、`robots.txt`も確認しません。ページの描画にも同じ制限が適用され、ログインやCAPTCHAを回避することはできません。未対応のURLスキームは取得せず、ブックマークとして保持されます。

## 保存先と言語

デフォルトの`data/`ディレクトリには、SQLiteデータベース、元のインポート、処理結果、提案バージョン、`settings.json`と、保存したキーがある場合は`credentials.json`が保存されます。バックアップの前にサーバーを停止してください。このディレクトリはGitの管理対象外です。独自のデータディレクトリも除外し、個人用コンテンツ、認証情報、モデルバイナリをGitの管理対象に含めないでください。

| 環境変数 | デフォルト |
| --- | --- |
| `BOOKMARK_DATA_DIR` | `data/` |
| `BOOKMARK_PORT` | `8765` |
| `OPENROUTER_API_KEY` | 未設定。保存済みキーがない場合に使用 |

実行例：

```sh
BOOKMARK_DATA_DIR=./my-bookmark-data BOOKMARK_PORT=8766 uv run --locked bookmark-organization
```

インターフェースの言語はデフォルトで**自動**です。使用可能なブラウザー設定のうち最も優先順位の高いものを使い、`ja`タグなら日本語、それ以外なら英語を選びます。設定がない、または使用できない場合は日本語になります。手動で選んだ**English / 日本語**はブラウザーのCookieに保存されます。言語を切り替えても処理範囲の選択と保存済みの作業は保持されますが、元データや生成済みの名前は翻訳されません。

## 開発

このアプリはFastAPI、Jinja2、HTMX、TypeScript、SQLiteを使用しています。Pythonコードは[`src/bookmark_organization/`](src/bookmark_organization/)、フロントエンドのソースは[`frontend/`](frontend/)、チェック類は[`tests/`](tests/)にあります。`src/bookmark_organization/static/`内の生成アセットはGitの管理対象外です。

リポジトリのディレクトリで、該当するチェックを実行します。

```sh
uv run --locked ruff check src tests
uv run --locked ruff format --check src tests
uv run --locked ty check src
uv run --locked pytest -q
npm run lint
npm run typecheck
npm run build
uv run --locked python tests/smoke_app.py
```

単体テストでは合成HTML、一時データベース、模擬通信を使用します。ブラウザースモークテストにはビルド済みアセットとPlaywright Chromiumが必要です。テスト用の模擬推論を使って実際のアプリサーバーを起動し、デスクトップ幅とモバイル幅で両言語のワークフローを確認します。

実モデルを使う別の受け入れテストは次のとおりです。

```sh
uv run --locked python tests/smoke_local_models.py --settings data/settings.json
```

Codexの実モデル分析を2つのテスト本文で確認する場合は、固定モデルとChatGPTログインを使う次のコマンドを実行します。

```sh
uv run --locked python tests/smoke_local_models.py --settings data/settings.json --codex
```

`--codex`は分析のみの検証で、埋め込み・実サイト取得・エクスポートは行わず、保存済みのアプリ設定も変更しません。

`--codex`も`--custom`も指定しないテストには、LM Studio、`lms` CLI、上記2つのGGUFモデルと一致する設定が必要です。実モデルによる検証記録はLM StudioとCodexの分析を対象としています。Ollamaのアダプターは模擬通信を使う単体テストで確認されています。OpenRouterのリクエスト形式、認証エラー、用途別のモデル取得、プロバイダー併用、キーの隔離は模擬通信で確認します。合成チェックでは実モデルとの互換性や認証済みOpenRouter推論を確認できません。

設計の詳細と検証記録は、[インターフェース仕様](docs/design/README.md)および[実装計画と検証履歴](PLANS.md)を参照してください。

現在選択中のプロバイダーでカスタム命名・分類、埋め込み、書き出しを検証する場合：

```sh
uv run --locked python tests/smoke_local_models.py --settings data/settings.json --custom
```

埋め込み用ランタイムが使えない場合は`--analysis-only`を追加すると分析のみを確認できます。公開資料のテスト本文2件を使用し、実サイトの取得やアプリ設定の変更は行いません。
